# 制作画像クリエイター

画像を配置・加工して、PC版・SP版の一枚画像を生成するツールです。
ブラウザタブには「制作画像クリエイター」と表示されます。

## ページ構成（react-router-dom）

| パス | 機能 |
|---|---|
| `/` | トップ画像作成: デザインパターン（A-1〜D-2）の枠に沿って画像を配置し、PC版・SP版の一枚画像を生成 |
| `/gradient` | グラデーション作成: 1枚の画像にグラデーションを重ねて出力 |

## 主な機能

### レイアウト編集（トップ画像デザイン）

- **デザインパターン7種**: A-1（全面1枚）／B-1（縦2分割）／B-2（大＋小の縦2分割）／C-1（右大＋左縦2分割・曲線境界）／C-2（縦3分割）／D-1（大1枚＋下3分割）／D-2（大＋右縦3分割）から選択
- **枠はキャンバスを隙間なく埋める矩形**で、パターンごとに枠数・構成・キャンバス初期サイズが変わります（PC=960×600、SP=640×380［A〜C］・640×540［D］）
- **C-1 の大画像と左サブ画像の境界は大きな円弧**（直線分割ではない）。この曲線はプレビュー・書き出しの双方に反映されます
- **B-2 / D-2 は SP 版が存在しない**ため、SP 版はそれぞれ B-1 / D-1 の枠構成・サイズで出力します（PC 版は B-2 / D-2 のまま）
- パターンを切り替えても写真は保持され、各写真の切り取り状態（ズーム・位置）はモード（PC/SP）ごとに独立して調整できます
- **キャンバスの幅・高さは数値入力またはハンドル（左右＝幅・下端＝高さ）で変更**。各枠は比率を保って追従します

### 画像のアップロード・差し替え・削除

- 対応形式は jpg / jpeg / png / webp
- 空きスロットは**クリックまたはドロップ**で直接画像を追加できる（下部のアップロード枠は不要）
- 画像ありスロットにホバーすると右上に「変更」「削除」ボタンが表示される
  - **変更**: ファイル選択でそのスロットの画像を差し替え
  - **削除**: 画像を外して空きスロットに戻す
- ドロップは画像ありスロットにも常時受け付け（上書きで差し替え）
- 画像を差し替えたときは、その画像の調整状態（ズーム・位置）をリセット

### グラデーション作成（`/gradient`）

- **1枚の画像**をキャンバス全面に配置し、**左右フェード**のオーバーレイを重ねて出力（余白部分にもかかる）
- キャンバスは PC・SP とも 960×345 が既定
- グラデ設定:
  - **向きはモードで固定**（選択 UI なし）: PC版=右フェード（右端から内側へ減衰）／ SP版=左右フェード（両端から内側へ減衰）
  - **開始位置 / 終了位置**: 既定値は PC=開始45%／終了70%、SP=開始20%／終了30%（枠端からの距離 %）。編集可能
  - **フェード色**（カラーピッカー＋hex 直入力）と**開始・終了の不透明度**
- プレビュー操作: ドラッグ移動／ホイールズーム（カーソルアンカー）／ダブルクリックでフィット⇔100%／矢印ナッジ／+/-／Ctrl+0,1／右下 % バッジの数値入力パネル
- サイズ変更: 下端ハンドル＝キャンバス高さ、左右ハンドル＝キャンバス幅のドラッグ変更（Toolbar の数値入力も可）
- PC版・SP版はキャンバスサイズ・調整状態・グラデ設定とも完全独立

### 書き出し（エクスポート）

- レイアウトページ・グラデーションページ共通: エクスポートダイアログで **書き出し形式を選べます**（**JPG が既定**／PNG／WebP）
- 形式に応じてダウンロード時の拡張子も変わります（例: `output_pc.jpg` / `output_pc.png`）

### 画像の切り取り位置・ズーム調整（スロット単位）

3つの操作経路（マウス / キーボード / 数値入力）で同じ結果になります。

| 操作 | 内容 |
|---|---|
| ドラッグ | 切り取り位置の移動（フレーム端でクランプ） |
| ホイール | カーソル位置を基準としたズーム |
| ダブルクリック | フィット（cover）⇔ 100% 切り替え |
| Tab / Shift+Tab | スロット間のフォーカス移動 |
| 矢印 / Shift+矢印 | 位置を 1px / 10px 移動 |
| + / - | ズーム段階変更 |
| Ctrl+0 / Ctrl+1 | フィット / 100% |
| 右下の「%」バッジ | 調整パネル（ズーム%・オフセットpx の数値入力＋ショートカット一覧） |

### 制約（仕様）

- **拡大禁止・縮小自由（両ページ共通）**: 元画像サイズを超える拡大は不可（ズーム上限 100%）。縮小は下限 5% まで自由で、周囲に余白が出てもそのまま出力されます
- **縮小時のはみ出し配置も可能**: 縮小した画像の一部を意図的にフレーム外へ出し（トリミング的に不要な端を隠し）、残りを表示できます。はみ出した部分は出力に描画されません
- **余白警告**は、元画像自体が枠より小さい場合（100% 表示でも余白ができる場合）のみ表示。意図的に縮小・はみ出しさせた場合は表示されません
- PC版・SP版のレイアウト設定と切り取り状態はそれぞれ独立
- 画像を差し替えたときは、その画像の調整状態をリセット
- 初回アクセス時にショートカット概要を1度だけ表示（localStorage で管理）

## 技術構成

- React 19 + TypeScript + Vite + react-router-dom
- プレビューは `<canvas>` 1枚（devicePixelRatio 対応）。エクスポートと同一の描画関数（`src/lib/canvas-renderer.ts` の `drawLayout` / `drawGradientLayout`）を流用し WYSIWYG を保証
- 幾何計算の唯一の情報源は `src/lib/layout.ts` / `src/lib/gradient.ts`
- 切り取り状態は正規化座標モデル（`{ zoom, focusX, focusY }`、`src/lib/transform.ts`）

## E2Eテスト（Playwright）

```bash
npm run test:e2e           # 全テスト（レイアウト67項目 + グラデーション31項目）を並列実行
npm run test:e2e:resize    # レイアウトページのみ実行
npm run test:e2e:gradient  # グラデーションページのみ実行
```

- レイアウトページ: デザインパターン切替（枠数・キャンバスサイズ・B-2/D-2 の SP フォールバック）、C-1 の円弧境界（プレビュー・出力のピクセル検証）、クリック／ドロップによるアップロード、キーボード/ドラッグによる調整、数値入力パネル、PC/SP独立性、エクスポート出力（PNGサイズ・ピクセル検証・書き出し形式 JPG 既定／PNG 切替）、余白警告、スロットの変更／削除、キャンバス幅・高さの変更など 67 項目
- グラデーションページ: ナビ遷移、方向固定（PC=右／SP=左右）とデフォルト位置の検証、アップロード／差し替え、移動・ズーム、フェード描画のピクセル検証、色変更、出力 PNG の検証、書き出し形式（JPG 既定／PNG 切替）、サイズ変更など 31 項目
- 初回のみ `npx playwright install chromium` が必要です。
- Viteのdevサーバーを自動で起動し、テスト後に停止します。
- `test:e2e` は2つのテストファイルを**並列実行**します（各テストが独立したサーバー・一時ファイルを使うため競合しません）。反復作業中などは個別実行スクリプトの利用を推奨。

## Git の運用フロー（GitHub Flow）

- **main ブランチ**: 常にデプロイ可能な状態を維持（直接コミット・マージ不可）
- **機能追加時**: `feature/xxx` ブランチを切って実装し、PR で main へマージ
- **バグ修正時**: `fix/xxx` ブランチを切って修正し、PR で main へマージ
- main・develop への push 時に GitHub Actions が自動で GitHub Pages へデプロイ（公開内容はブランチごとに独立。詳細は「GitHub Pages デプロイ」参照）

### ブランチ命名規則

| 種別 | 命名例 |
|---|---|
| 機能 | `feature/xxx` |
| バグ修正 | `fix/xxx` |
| ドキュメント・CI 等 | `chore/xxx` |

### コミットメッセージ規則（Conventional Commits）

- `feat: グラデーション機能追加`
- `fix: ドラッグ累積バグ修正`
- `chore: コピーライト追加`

## GitHub Pages デプロイ

GitHub Actions で自動ビルドし、**gh-pages ブランチ**経由で公開します（ブランチごとに独立）。

| ブランチ | ワークフロー | 公開先 URL | 更新範囲 |
|---|---|---|---|
| `main` | `.github/workflows/deploy-pages-main.yaml` | `https://<user>.github.io/<repo>/` | ルート全体（`dev/` を除く） |
| `develop` | `.github/workflows/deploy-pages-develop.yaml` | `https://<user>.github.io/<repo>/dev/` | `dev/` のみ |

- 各ワークフローは自分の担当ディレクトリのみを更新するため、**develop への push が main の公開内容に影響しない**（逆も同様）
- 同時 push 時は `concurrency`（グループ `pages-publish`・キャンセルなし）により直列実行され、競合しない
- アセットパスは CI で `vite build --base=/seisaku-image-creator/`（develop は `/seisaku-image-creator/dev/`）を指定して解決
- ルーティングは `HashRouter` を使用（GitHub Pages には SPA フォールバックがないため）
- ブラウザ内ナビゲーション: `https://<user>.github.io/<repo>/#/gradient`（develop では `https://<user>.github.io/<repo>/dev/#/gradient`）

### 初回セットアップ（一度だけ）

1. Settings → Pages → Build and deployment の Source を **Deploy from a branch** に変更
2. Branch: **gh-pages** / Folder: **/ (root)** を選択して Save

gh-pages ブランチはワークフロー初回実行時に自動生成されます（手動実行する場合は Actions の「Deploy Pages (main)」から workflow_dispatch を実行してください）。
